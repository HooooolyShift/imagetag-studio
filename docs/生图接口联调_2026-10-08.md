## 一·补　取消的竞态修复（2026-10-08 晚，用户报"偶发点了停止还在跑"）

根因有三条，都在旧实现里：

1. **排队中的任务停不掉**：只发**无参数** `/interrupt`，而它只打断"正在执行"的那一个。
   我们的 prompt 还在排队（ComfyUI 被 DLC 窗口或上一次任务占着）时，稍后照样会被执行 —— 偶发就是这个。
2. **提交与取消撞车**：取消发生在 `submit()` 之前一点点，那条已经进队列，而循环里的标志位检查已经过去了。
3. **状态竞争**：`_gen_running` / `_gen_cancel` 是裸标志位，在不同 HTTP 线程间读写，
   会出现"取消上一轮把刚开始的新一轮也带走"、"两个并发请求同时通过 already_running 检查"；
   无参数 `/interrupt` 还会把**其他客户端**的任务一起打断。

修法：

- 状态收进 `_gen_lock` 保护的 **epoch**（`gen_begin/gen_end/gen_cancelled/gen_set_prompt/gen_cancel_current`，
  见 `app/lan_api.py`）：取消只对"发起取消时那一轮"生效；
- ComfyUI 侧改**定向**取消：`POST /queue {"delete":[pid]}` + `POST /interrupt {"prompt_id": pid}`
  （本机 0.39 实测两者都支持；`prompt_id` 不匹配时服务器只记日志，不动手）；
- 任务线程在**每张提交前、提交后、wait 循环里**都检查自己那一轮的取消标记；`wait(should_stop=…)`
  让取消后约 2 秒内收尾（不然排队项被删掉后 /history 永远不出现，会白等到超时）；
- 没有本机任务在跑时，`/api/gen/interrupt` **不碰 ComfyUI**；
- `ComfyClient._post_nobody()`：`/queue`、`/interrupt` 返回空 body，原来用 `_post()`（内部 json.load）
  会抛 "Expecting value" 并被 except 吞掉，导致成功删队列却报 `deleted:false`。

验证（`%TEMP%\gen_race_test.py`，**11 项全过**）：

| 场景 | 结果 |
|---|---|
| A 排队中取消 | 占位任务还在跑（未误伤）、我们那条从队列消失、`/history` 无记录、没出图 |
| B 提交瞬间取消 | 任务线程补刀，以 `gen_failed{已取消}` 收尾、没出图 |
| C epoch 隔离 | 取消上一轮后立刻开新一轮 → 正常出图，没被带走 |
| D 三路并发 `/api/gen/run` | 只有一个 `started:true`，其余 `already_running` |

## 二、修掉的 5 个真 bug

1. `models.json` 的 `target` 被多拼了一层 `models`：全部清单项都被误判成"本机没有"，
   下载还会落到 `models\models\vae\…`（平板会以为要重下 20GB）。误建目录已清理，重复文件走回收站。
2. `/history` 里"执行失败"和"跑完没图"长得一样：`wait()` 静默返回空列表，用户只看到"没出图"。
   现在解析 `status.messages` 抛真实原因。
3. IP-Adapter / ControlNet 与底模架构不配套：ControlNet 会报
   `y is None, did you try using a controlnet for SDXL on SD1?`，
   而 IP-Adapter 不报错、只出噪声图。现在 `checkpoint_arch()` 读 safetensors 头部自动配对。
4. 新版 ComfyUI 下拉定义换成 `["COMBO", {"options":[…]}]`：旧解析把 `"COMBO"` 拆成
   `['C','O','M','B','O']`，`UpscaleModelLoader` 的模型名被解析成 `"C"`，提交即失败。
   现在两种写法都认（`ComfyClient._parse_enum`）。
5. `LatentUpscale` 的 width/height 是图像像素：自己先 `//8` 会得到 1/8 尺寸的图
   （要 1024 出了 128）。已修。

## 三、"为什么那边出的图好看、这边不可名状"

**是参数，不是接口。** PC 侧接口冒烟测试一开始用了 SD1.5 时代的参数
（512×512 / 8 步 / 短提示词），而 SDXL 的原生分辨率是 1024，低于 ~0.6MP 会糊成一团。

对照实验（同一个接口、同一台机器、同一张卡）：

| 参数 | 结果 |
|---|---|
| 512×512 / 8 步 / 短负向 | 色块、不成画 |
| 1024×1024 / 28 步 / CFG 5 | 干净成画，27s |
| DLC 预设 `sdxl_splash_1536x648`（60 步 / quality_prefix / 长负向） | 和生图端出的一个水平，51s |

结论：想复现生图端的质量，走 `preset` 参数即可（接口已支持，会自动套
quality_prefix + 负向 + 步数）。

## 四、分辨率的正确答案（用户问"上限能不能更高"）

不要硬开大分辨率：8GB 显存上 SDXL 出 2048² 基本必 OOM，超训练分辨率还会出重复肢体。

正解是先出 1024，再放大：

- `/api/gen/upscale`（纯 ESRGAN 超分）：1024→4096 只要 9 秒，无彩噪，推荐。
- `/api/gen/hires`（潜空间放大 + 低 denoise 重采样）：会长新细节，但头发边缘会出彩噪/重影
  （denoise 0.3 也还有；DLC 预设里本来就写着"二段放大与锐化都关掉"）。
- 想要"又大又有细节又干净"：先 `upscale` 再 `hires`，denoise 压到 0.15~0.25。

尺寸边界 256–2048（8 对齐），由 `/api/gen/info → limits` 下发，客户端照它画滑杆。
放大模型清单新增两项：`upscale-anime-4x`（Real-ESRGAN anime 6B，18MB，二次元）、
`upscale-4x-ultrasharp`（67MB，写实/通用）。

## 五、给生图端（DLC 界面）的待办

1. 分辨率调节：DLC 窗口已有"尺寸"输入框（256–4096、步进 64、默认 1024），
   建议改成照 `/api/gen/info → limits`（256–2048、8 的倍数）画，
   且不要给 SDXL 提供 512/768 这种档位。
2. 加"放大"入口：默认走 `/api/gen/upscale`；`hires` 作为可选项并标注"可能出彩噪"。
3. 加"图生图 / 图融合"入口：`/api/gen/img2img`。换装用 denoise 0.55~0.65；
   融合用 blend_factor 0.25~0.3 + denoise 0.7~0.85，否则会出双重曝光那种重影。
4. 默认底模换成 SDXL：SD1.5 已弃用（用户 2026-10-08 明确），
   DLC 自己的默认值也请跟着改（WAI-illustrious / NoobAI）。
5. 模型清单里已加两个放大模型项，如果生图端也在改 `models.json`，注意合并。
