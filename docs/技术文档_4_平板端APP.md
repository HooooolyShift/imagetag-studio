## 一、需求（用户 2026-10-07 整理）

### 1) 三端局域网互联（PC ↔ 安卓；安卓 ↔ 安卓不需要）
- 三端（PC / 平板 / 手机）都走**局域网**。
- **自动查找设备并显示设备列表，选中即连接**（不用手输 IP）。
- 同一局域网下要**尽量吃满带宽**（原图/缩略图传输别龟速）。
- 连接后，移动设备**除了访问本地库，还能访问 PC 库**。

### 2) 图库自带文件索引
- 把 **K 盘（或其它存图库的盘）直接插到平板/手机上**（OTG/读卡器），移动端要能
  **看到和 PC 一样的图库树**（同一套目录结构 + 同一套"文件名即 tag"解析）。

### 3) 平板的两档模式
- **未连接 PC**：只开放「图片浏览」+「标签图谱」两个功能。
  - 图片浏览只访问**本设备目录**，而且**只匹配本应用创建的文件夹**（例如 `ImageTags`），
    **不匹配 DCIM / Pictures 这类系统相册目录**。
  - 要能**查看原图**。
- **已连接 PC**：解锁**全功能模式**——功能与 PC 端**完全同步**，平板相当于**远程遥控器**，
  **算力全在 PC 端**（审核、打标、扫描、生成缩略图都在 PC 跑，平板只负责显示与操作）。
  - 连接后可访问 PC 目录。
  - **审核功能必须保留**（平板屏幕大，布局不用大改，基本沿用 PC 端布局）。
  - 标签图谱等功能也要保留。

### 4) 同步与缓存
- **每次连接自动同步 tag 库**；连接期间**实时同步**（PC 端改了 tag/库，平板立刻反映）。
- **尽量避免缓存爆炸**：及时清理不再需要的缩略图缓存。
- 打开大图时**自动加载原图，但不真正保存到平板**（用完即释放，不落盘）。

### 5) 技术选型约束
- 移动端用 **WebUI**（网页技术栈）。
- 动画遵循 **`motion-web` skill** 的规范（动效/手感/性能那套），**允许适度简化以保证性能**。
- 开发调试用**谷歌模拟套件**（Android 模拟器 / 浏览器设备模拟）；
  ⚠️ **当前可能有另一个会话在用模拟器开发，启动前先确认，别互相干扰**（见第四节）。

## 二、与 PC 端的数据交换（草案 v0.1，待与 PC 端会话冻结）

- 图库目录结构：`K:\ImageTags`（图库）/ `K:\pictures`（来源）；**文件名即 tag**，首位为分级
  （全年龄 / R15 / R18 / R18G，**没有 R16**）；系列 = 文件夹 + 页码文件名。
- PC 端数据库：SQLite `library.db`，表结构见 `app\store.py`
  （`files / tags / file_tags / taxonomy_edges / series / roots / categories / nodes / regions / dup_feedback` 等）。
- **连接模式**：平板不直接读 PC 的 `library.db`（会锁库、也拿不到实时变更），而是走 PC 端提供的**局域网 API**；
  每次连接全量拉一次 tag 词典（或增量），之后靠 WebSocket 增量推送。
- **离线/插卡模式**：移动端按"应用专属目录名"（默认 `ImageTags`）扫描本地存储与 OTG 盘，
  解析文件名里的 tag，建立**本地索引**（自己一份，不依赖 PC）。
- 缩略图：优先复用 PC 端 `<data_dir>\thumbs\`；移动端只缓存"当前浏览用得到的"，定期清。

## 三、PC 端需要配套提供的能力（跨端契约，同步写进《技术文档 1》）

1. **局域网服务**：HTTP + WebSocket（同端口），握手带设备名与版本号。
2. **设备发现**：UDP 广播或 mDNS；PC 端 UI 出「已连接设备管理」菜单。
3. **配对/授权**：一次性配对码或确认弹窗，避免同网段任意设备接入。
4. **接口**：图库树、分页缩略图、原图按需流式传输（支持 HTTP Range，方便大图与断点）、
   tag 词典、审核队列读写、图谱数据、批量操作转发（算力在 PC）。
5. **实时同步**：tag/库变更用 WebSocket 推送；平板断线自动重连并补拉增量。
6. **带宽**：原图流式 + Range；缩略图按屏宽分级（别拿 4K 原图当缩略图拉）。

## 四、协作注意（模拟器 / 端口）

- **启动 Android 模拟器前先检查**：`adb devices`、是否已有 `emulator.exe` / Android Studio 在跑；
  被别的会话占用就换 AVD 或等对方释放，**不要杀别人的进程**。
- 固定端口要登记在本文档：PC 端局域网服务端口、WebUI 开发端口（如 5173/8080），避免三端抢端口。
- 调试优先用"浏览器设备模拟"；需要 OTG、文件系统权限等真机特性时再上模拟器/真机（本机有 S24 Ultra 可连）。

## 五、方案冻结 v1.0（2026-10-07，冻结的是"骨架阶段"；标 ⏳ 的条目待 PC 端会话确认）

### 5.1 架构总览（三层，UI 只有一份）

```
┌─ WebUI（HTML/CSS/JS，无构建步骤，手机+平板共用一套） ─────────────┐
│  浏览（网格+大图） · 标签图谱 · 筛选/搜索 · 设置/缓存管理          │
│  └─ 数据源适配层（同一个接口，三种实现）                          │
│     ① NativeBridge  →  Android WebView 壳（本地/OTG 目录）        │
│     ② DevFs         →  浏览器开发模式（File System Access / mock）│
│     ③ PcClient      →  连 PC 后走局域网 API（⏳ 待 PC 端提供）     │
└───────────────────────────────────────────────────────────────┘
              ▲ JS 桥（window.imtagNative）
┌─ Android WebView 壳（Java，极薄，只提供能力不画界面） ─────────────┐
│  · 目录枚举（SAF/DocumentFile + MediaStore） → 只认"应用专属目录"   │
│  · 读原图字节（content:// 流）/ 缩略图字节                        │
│  · 横竖屏、全屏、返回键、存储权限申请                             │
└───────────────────────────────────────────────────────────────┘
                          局域网（⏳ PC 端 1.5 落地）
┌─ PC 端局域网服务（HTTP + WebSocket 同端口） ──────────────────────┐
│  设备发现 · 配对 · 图库树 · 缩略图 · 原图 Range · tag 词典        │
│  · 审核队列读写 · 图谱数据 · 批量操作转发（算力全在 PC）           │
└───────────────────────────────────────────────────────────────┘
```

**为什么必须有壳（不是"想用原生"）**：需求 2 要求插上 OTG 盘就能看到与 PC 一样的图库树，
而**浏览器拿不到 Android 文件系统**——`showDirectoryPicker()`（File System Access API）在 Android
Chrome/WebView 上不可用，网页只能通过 `<input type=file>` 拿到用户手选的单个文件。
所以目录枚举必须由壳提供，WebUI 通过 JS 桥调用。壳里**不写任何业务 UI**，
这样手机端/平板端共用同一套 WebUI，两端只在断点与布局上分叉。

  android\          WebView 壳（Java；沿用 死了么app 2 的"零 Gradle"打包脚本模式）
  tools\            dev-server.cmd、截图自检脚本、词典子集生成脚本

### 5.3 数据层规则：只写一次（对应 PC 端实现）

WebUI 里用 JS 实现一遍，PC 端 Python 实现为准绳，两端用同一批样例对拍：

| 规则 | PC 端出处 | WebUI 侧 |
|---|---|---|
| 文件名/文件夹名取 tag | `app/naming.py:parse_tags_from_name` | `js/rules/tag-parse.js` |
| 基础名与 tag 拆分 | `naming.split_name`（支持多个方括号块） | 同上 |
| 分级四档与别名归一 | `app/config.py:RATING_TAG` + `library.py` 别名表 | `js/rules/rating.js` |
| 中文显示名优先级 | `app/tag_i18n.py:label()` | `js/rules/zh.js` |
| 系列识别 | `series` 表 / 页码文件名 | `js/rules/tag-parse.js:detectSeries` |

离线档**不做**："最具体子标签"裁剪（那需要 taxonomy_edges，只有 PC 库有）——
离线时按文件名原样展示，连上 PC 后再按 PC 的规则显示，避免两端显示不一致却被误认为是 bug。

### 5.4 交换格式 v0.1（修订）

- **连接模式**：不读 PC 的 `library.db`（会锁库且无实时性），全部走局域网 API（5.1 第三层）。
- **离线模式**：不依赖 PC 任何产物，自己扫"应用专属目录"（默认 `ImageTags`，可配置）建本地索引
  （IndexedDB）；**只认应用自建目录，不扫 DCIM/Pictures**（用户明确要求）。
- **缩略图**：离线档用原图 + 懒加载（`<img loading=lazy>` + 内存 LRU），**不落盘**；
  连 PC 后改用 PC 端分级缩略图（`thumbs\` 的 320px 或按屏宽的更大档）。
- **词典**：离线档内置一份"常用子集"（从 `app/tag_zh_dict.json` 抽本库用到的标签）；
  连 PC 后整份由 PC 推送，保证两端显示一致。

### 5.5 动效规范（按 `motion-web` skill 落到可执行约束）

本端是**应用界面**不是营销页，所以取 skill 里"手感/性能/可验证"那半边，不搬落地页那套：

- **token 层单独立文件**（`css/tokens.css`）：时长 `120/180/240/320ms`，缓动
  `cubic-bezier(.2,.8,.2,1)`（进场）/`cubic-bezier(.4,0,1,1)`（出场）；弹簧参数只用于跟手元素。
- **跟手元素（大图拖动/双指缩放）不用 transition**：走 rAF + `1-exp(-k·dt)` 帧率无关平滑
  （skill `handfeel.md` §7），k 取 12~18；松手做速度衰减，不做回弹到底。
- **只动 `transform` / `opacity`**，不动 `width/height/top/left`；网格滚动里不给每个格子加
  `transition`（几千个节点会让合成层爆掉）。
- **`prefers-reduced-motion` 全量降级**为直接切状态，不隐藏内容。
- **静止帧也要成立**：先保证不动的界面（网格、筛选条、大图页、图谱）本身组织清晰，
  再往上加动效；这条是 skill 反复强调的门禁。
- **性能预算**（骨架阶段就守住）：首屏 JS ≤ 150 KB（不引第三方框架）、
  网格同时挂载 ≤ 120 个缩略图节点（超出用分页/回收）。
