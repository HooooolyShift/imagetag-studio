## 一、目标（未开工，先把边界定清楚）

在 Android 平板上浏览 / 检索 PC 端「图片标签工坊」的图库：按 tag 检索、看缩略图与大图、
（可选）做审核与打标，并支持 MIX 等文件管理器能识别的文件名 tag 规则。
定位为**只读/轻编辑的伴生端**，重活（扫描、打标、模型训练）仍在 PC 端做。

## 二、与 PC 端的数据交换（待冻结，先按这个草案走）

- PC 端图库目录：`K:\ImageTags`（图库）/ `K:\pictures`（来源）；文件名即 tag，格式见《技术文档 1》
  （首位是分级：全年龄 / R15 / R18 / R18G，其余为中文标签名，系列文件夹带标签后缀）。
- 数据库：PC 端 `library.db`（SQLite），表结构以 `app/store.py` 为准。
- 交换格式（建议，待两边确认后写死）：
  1. **首选**：直接复制 `library.db` 到平板（只读打开）；表结构变了要版本号字段兼容。
  2. 备选：PC 端导出 JSON 索引（路径、缩略图、tag 列表、分级、系列），平板端建本地索引缓存。
- 缩略图：PC 端 `<data_dir>\thumbs\` 已生成，可直接复用（注意尺寸/命名规则）。

## 三、技术栈（建议，待确认）

- Kotlin + Jetpack Compose（平板横竖屏自适应、大屏分栏）；Room 读索引；Coil 加载图片；
  MediaStore / SAF 访问图库目录；如需网络同步，用局域网 HTTP（PC 端起个小服务）而不是公网。
- 参考已有的本机 Android 项目经验：`E:\文档\ChatGPT\死了么app`、`死了么app 2`。
- 机器上已有 S24 Ultra 可做真机调试（参见"确认访问连接的S24 Ultra手机"会话）。

## 四、必须复用的既有规范（避免两端不一致）

- 分级只有四档：全年龄 / R15 / R18 / R18G（**没有 R16**）。
- tag 父子从属关系：显示时优先显示更具体的子 tag（有"白裙子"就不显示"裙子"）。
- 中文显示：优先用"中文备注"，词典在 `app\tag_zh_dict.json` / `app\tag_zh_corrections.json`（可复用）。
- 系列：一组图片合并为一个文件夹，文件夹名带 tag，内部文件名为页码。
