### 为什么放弃 Kotlin + Compose（原方案作废）

- 用户明确要求移动端用 **WebUI**；平板端已按 WebUI + 局域网协议推进，
  手机端若走原生就会与平板端分叉，违背"共用同一套数据层与协议、别各写一份"。
- 附带好处：本机不用再下载 Gradle 8.7 + Compose 全家桶（约 300~400 MB）；
  WebView 壳走已验证的免 Gradle 链路，构建秒级，也不怕中文路径。
- 代价：WebView 里做大图解码、长列表滚动要注意内存与掉帧 —— 用 `motion-web` 的性能规范兜底
  （虚拟列表、按屏宽取图、大图用完即释放）。

## 四、数据来源与交换（两条主线 + 一条备选）

与平板端**同一套**（《技术文档 4》第二、三节），手机端只是用的功能少：

**A. 本地 / OTG 扫描（离线，手机端主线）**

- 只扫**本应用目录**（默认 `ImageTags`）+ 用户手动添加的其它目录，**不碰 DCIM / Pictures**。
- 按"文件名即 tag"解析 `[标签 标签]`（首位是分级，四档、**没有 R16**），建本地索引（IndexedDB）。
- 原图就在本地 / OTG 盘上，所以**能看原图**，这条正好满足用户"要能查看原图"的要求。

**B. 连接 PC（局域网，和平板端共用同一套协议）**

- PC 端提供 HTTP + WebSocket（同端口）、设备发现、配对授权、缩略图分页、原图 Range 流式（见《技术文档 4》第三、四节）。
- 手机端**只用其中这几类接口**：图库树、缩略图、原图、tag 词典、图谱数据。
  **不碰**审核队列 / 打标 / 批量操作 —— 那是平板端的全功能模式。
- 连接后每次自动同步 tag 库、连接期间实时增量（两端同一套 WebSocket 逻辑）。

**C. PC 导出的离线快照包（备选，是否保留待确认）**

给"不想连 PC、图库也不在手机上"的场景用。格式（与平板端一致，**别两端各写一套**）：

```
imagetag-mobile-<yyyymmdd>.zip
├─ manifest.json      # format / format_version / generated_at / roots / counts / rating_levels / blur_default
├─ tags.json          # [{id, name, zh, category, category_label, count, r18:0/1}]
├─ tag_tree.json      # {"child_map": {父标签: [子标签…]}}   ← most_specific 用
├─ zh_index.json      # {"中文名": "规范标签名"} = tag_zh_dict + corrections + fix_history + 库内手填
├─ pinyin_index.json  # 可选：拼音 → [规范标签名]（复用 app/pinyin_zh.json）
├─ files.jsonl        # 每行一张图：{id, root_id, rel, name, ext, w, h, rating, series_id, page_no, missing, tags, zh}
├─ series.json        # [{id, dir, name, tags, page_count, first_file_id}]
├─ taxonomy.json      # 图谱：nodes + taxonomy_edges + layout（PC 端摆好的位置）
└─ thumbs/<id%256>/<id>.jpg   # 320px JPEG（对齐 imaging.make_thumb）
```

要点（A / B / C 通用）：

- **文件名里的标签是中文（`disk_label`）**，A 方案下手机只拿到中文名，所以需要
  `zh_index.json`（内置进 App 或首次同步时下发）；B 方案下由 PC 端直接给规范名。
- 分级是显式值，**不要从文件名首位去猜**；四档且没有 R16。
- 缩略图沿用 PC 的 320 px 档；`rel` 保留相对路径，便于按它映射到手机 / OTG 上的原图。

**图谱（手机端第二个功能）需要的数据**：

- B 方案：直接用 PC 的 `nodes` + `taxonomy_edges` + `layout`（用户在 PC 上拖过的位置照搬，观感一致）。
- A 方案：手机上只有一堆 tag，没有 PC 的图谱 —— 只能现场构图（按 `category` 分组 / 按共现关系算力导向）。
  这属于要跟用户确认的预期（见第九节）。

## 五、与平板端共享的数据层（Web 版模块划分）

`core` 是唯一的数据层，**由平板端的 WebUI 骨架承载，手机端复用，不许另起一套**。
规则与 PC 端 Python 实现逐条对齐：

| core 模块 | 职责 | 对齐 PC 端 |
|---|---|---|
| `core/model` | `Tag` / `ImageItem` / `Series` / `Rating`；四档分级（全年龄 / R15 / R18 / R18G，无 R16）与配色 | `config.RATING_*` |
| `core/parse/filename-tags` | 解析文件名 / 文件夹名里的 `[标签 标签]`，末尾可多块；非法字符替换、空格分隔 | `app/naming.py`（`split_name` / `parse_tags_from_name` / `sanitize_tag`） |
| `core/parse/zh-index` | 中文名 → 规范标签名（词典 + 修正 + 历史 + 库内手填，按"有图 > 下划线少 > 名字短"择优） | `app/tag_i18n.py`（`zh_index` / `_norm`） |
| `core/source/local` | 扫 `ImageTags` 目录 + OTG 盘、建本地索引（含增量与缓存清理） | `library.scan_root` 的命名/分级规则 |
| `core/source/lan` | 局域网 API 客户端：发现 / 配对 / 图库树 / 缩略图 / 原图 Range / WebSocket 增量 | — |
| `core/query` | 检索：中文 / 英文 / 拼音 / 分级 / 系列 | `app/library.py` |
| `core/query/most-specific` | 有子标签就不显示父标签（带 visited 防环） | `library.most_specific_tags` |
| `core/graph` | 图谱数据：nodes / edges / layout 读取 + 离线构图 | `library` 的图谱部分 |

**一致性铁律**：`core` 的任何改动，手机端与平板端两个会话都要各自在自己技术文档（5 / 4）记一条；
若与平板端实现冲突，**先对齐再改**；跨端格式最终以《技术文档 1》为准。

## 八、风险与规避

| 风险 | 规避 |
|---|---|
| WebView 内存 / 掉帧（大图 + 长列表） | 虚拟列表、按屏宽取图、大图用完即释放；按 `motion-web` 的性能规范做，动效允许简化 |

| 本机 npm 不可用 | 用 pnpm；优先零依赖静态页，别引入大依赖树 |
| OTG / SD 卡读取权限 | SAF + 目录白名单（只认 `ImageTags`），不扫系统相册 |
| 缓存爆炸（缩略图越积越多） | 按《技术文档 4》第四节：只缓存当前浏览用得到的，定期清 |
| R18 / R18G 误显 | 默认模糊 + 设置项；沿用 PC 四档与配色，不自行新增档位 |
| 模拟器和别的会话抢资源 | 启动前先 `adb devices` / 看进程，**不要杀别人的进程** |
