# 图片标签工坊（ImageTagStudio）

本地、离线、可检索的图片打标工具：**二次元图 + 真人照片**自动打 tag，按 tag 检索与缩略图浏览，
把标签写进文件名/文件夹名（手机上用文件管理器直接搜得到），支持系列合并、标签体系图谱、
以及「给某个 tag 手动框选画面区域」这种区域级监督。

所有推理都在本机跑（RTX 4070 上用 CUDA，无显卡自动回落 CPU），不联网、不上传图片，也不受内容审核影响。

## 1. 怎么启动

### 用户从 GitHub 下载后怎么拿到模型和依赖？（三条路）

仓库里**只有源码、脚本、说明书**（几十 MB）：模型 1.74 GB 与 Python 依赖 2.87 GB 太大，
GitHub 仓库放不下（单文件 100 MB 限制），所以按下面三种方式获取：

| 方式 | 适合谁 | 怎么做 | 体积/耗时 |
| --- | --- | --- | --- |
| **① 源码 + 自动安装脚本**（推荐） | 能联网 | `git clone` 后运行 `tools\setup_env.ps1`（自动建环境、从国内镜像装 torch 等依赖、下载模型） | 下载约 5 GB，15~30 分钟 |
| **② Release 分卷**（无需网盘） | 完全离线、没网盘 | 到 Releases 下载 `payload.zip.001`、`.002`、`.003`，放在同一目录后双击 `合并并安装.bat`，自动合并并启动安装程序（可对照同目录 `SHA256.txt` 校验） | 下载 4.7 GB |
| **③ 网盘整包** | 国内网络 | README/Release 里给的网盘链接直接下 4.7 GB 完整包 | 下载 4.7 GB |

三条路最后得到的东西完全一样，装好后都是离线运行。更新则只需 **更新包（约 5 MB）**，
覆盖程序文件即可，不用重新下模型。

程序本身只带代码，模型按需从 HuggingFace（国内走 `hf-mirror.com`）下载，均为公开开源模型：

各模型版权与许可归原作者所有，本项目只做本地推理调用，不修改、不重新分发模型权重
（完整离线安装包里的模型同样来自上述仓库，供无网络环境使用）。

## 3. 打标引擎

| 引擎 | 作用 | 说明 |
| --- | --- | --- |
| **WD14**（ONNX，GPU） | 二次元图的标准 tag：人数、发色、服装、姿势、角色名等 1 万多个 | 角色名阈值默认 0.85、通用 0.35，可在设置里调；实测 4 张图 3.6 秒 |
| **CLIP 零样本** | 你自己新增的 tag（中文也行） | 每个 tag 可写英文提示词；类型不同用不同模板（服装用 `wearing {}`、人物名用 `the anime character {}`） |
| **人脸**（SCRFD + ArcFace） | 真人照片 → 人脸聚类 → 命名后自动给照片打人物标签 | 动漫脸不检测（这是刻意的） |
| **自训练探针** | 用你确认过的标注在线学 | 1 个样本就能学（few-shot，阈值自动收紧）；≥20 正样本 + 负样本后自动训练逻辑回归 |

**类型不是摆设**：新增 tag 时选类型（人物名/服装/人数/体位/场景/画风…），它会决定 CLIP 用的提示词模板；
另外给 tag 填 `hatsune_miku` 这类 WD14 英文名，WD14 的结果会直接映射到你的中文 tag 上。

**类型可以自己加**（工具栏「类型管理」，或标签管理里点「类型管理…」）：

- 新增/改名/删除类型，还能调整顺序（顺序决定左侧筛选树和下拉框里的排列）；
- 每个类型可以写自己的 **CLIP 提示词模板**（用 `{}` 代表标签名，用 `|` 分隔多条），
  例：新建「道具」类 → `a {} object | {} | holding {}`；
- 删除类型时，它下面的标签自动转到「其它」，标签本身不丢；
- 类型存在数据库里，所以老库升级会自动把内置 12 种写进去，你改过的不会被覆盖。

## 4. 新增库里没有的标签，后续能认出来吗？

能。四条路，按投入从低到高：

1. **零样本（0 样本）**：新建 tag + 写英文提示词（如 `a sex toy held in hand`）→ 点“CLIP 重打分”，
   几秒内给全库重新打分。适合 CLIP 词表里本来就有的概念；词表里没有的（特定小众物体）误报会偏多。
2. **1 个框 → few-shot**：在大图预览里打开“框选标注”，框住手里的物体 → 选标签 → 保存。
   系统立即学出该 tag 的「区域特征中心」，此后按这个区域的样子去找，阈值自动 +0.15~0.18 保证精度。
3. **以图找图（最快）**：选中一张有代表性的图（或它的某个框）→ 点 **查找相似图片** →
   按相似度列出全库结果 → 勾选真正相似的 → 右侧加同一个标签，一次标注一批。
4. **样本攒够自动变准**：同一 tag 累计 ≥5 个样本后阈值放宽，≥20 个正样本 + 负样本后自动训练分类器，
   之后它的判断基本不依赖 CLIP 词表了。

> 关于「局部标签到处命中」的问题（例如领带状物体被误判成领带）：系统用三层机制防住它——
> ① **位置先验**：从你的框里学这个 tag 的典型位置（有脸时按“相对人脸”的坐标算，比整图坐标稳）；
> ② **上下文裁剪**：框内 + 框外一圈各出一份特征，避免只看局部纹理；
> ③ **前置条件 requires**：给 tag 写条件标签，如「领带」要求同时出现「人物」，不满足就基本否决
> （判定对前置标签本身是宽松的，差一点没过阈值也算满足，避免误伤正确结果）。

## 4.5 审核：AI 打的标签不会直接生效

### 新增标签后会自动回扫

新建一个**带英文提示词**、且勾了「参与自动识别」的标签（不管是在标签面板、标签管理、类型管理还是审核台里建的），
程序会自动用 CLIP 对全库重打一遍分（走缓存特征，通常几秒），命中的图片会以**待审核**状态进审核队列。
不想每次都扫，可在设置里关掉「新建标签后自动全库扫描」；也可以随时用「更多 → CLIP 重打分」手动扫。

### 重复审核会不会冲突？

不会。审核全程**只改数据库状态，从不重写图片文件**：

- 标签是 `(文件id, 标签id)` 一行状态：待审核 / 已生效 / 已拒绝，确认只是改这行的状态；
- 自动扫描/回扫**只写「待审核」行，永远不会覆盖已确认或已拒绝的结论**（所以被拒绝的标签不会反复冒出来）；
- 已审过的图因为新标签再次回到审核区时，你只处理新冒出来的那几个，再存一次是幂等的，不会重复也不会丢数据；
- 文件重命名 / 收录进图库 / 并入系列都只更新数据库里的路径，审核引用的是文件 id，所以照常有效。

自动打标的结果先进入 **待审核**，只有你确认过的标签才算「正式生效」，才会写进文件名、才参与检索。

| 状态 | 含义 | 影响 |
| --- | --- | --- |
| 待审核 pending | AI 刚打上的 | 网格里显示黄色 `待审N` 角标，标线里带 `?` 前缀；不写文件名、不算正式标签 |
| 已生效 confirmed | 你确认（或手动的） | 正常检索、写文件名、参与模型训练 |
| 已拒绝 rejected | 你判断「不是这个标签」 | 不再出现，而且会作为**负样本**喂给模型 |

审核入口：工具栏 **审核待定标签 (N)**。界面里：

- 左边是待审队列（按待审数量排序），中间大图，右边逐个标签给 ✓ / ✗；
- **在标签表里点一行 → 图上立刻高亮这个 tag 对应的区域框**，便于核对偏差；
- 框不准就点「重新框选选中的标签」，直接在图上拖新框，旧框会被替换、区域特征立即重学；
- 快捷键：`A` 全部接受、`R` 全部拒绝、`1`~`9` 切换第 n 个标签、`空格` 保存并下一张、`←` 上一张；
- 右侧面板里也能右键单个标签：确认 / 拒绝 / 彻底删除；还有「确认全部待审 / 拒绝全部待审」一键过。
- **审核时可以补标签**（AI 漏标的场景）：
  - 右下角输入框打名字回车 → 直接生效（可先在旁边选类型），并立刻计入该标签的样本；
  - 「新建标签（类型/提示词/前置条件）…」→ 适合那种以后要靠 CLIP 自动找的标签，建完顺手打上；
  - 「相似图片的标签推荐」→ 从库里相似图片的已有标签里挑，双击即采纳；
  - 先输入标签名再点「重新框选」，会自动把该标签加到这张图并进入框选模式；
  - 已生效标签也能选中 → 高亮/新建/修正它的区域框。
- **审核界面能直接管系列**：下方「已有系列」面板列出所有系列（首页缩略图 + 文件夹名 + 页数），
  可一键「加入选中系列」（当前图按下一页并入）、「用当前图片新建系列」、「移出系列」（文件不动）。

**审核动作会立刻回馈模型**：确认 → 正样本（更新特征中心，够了就训练分类器）；拒绝 → 负样本。
所以越审越准，尤其是「泳装 / 领带 / 眼镜」这类容易误报的标签。

## 4.6 断电/关机也不怕：任务断点续跑

每个批量任务（WD14 / CLIP / 自动打标 / 人脸 / 区域精修 / 重打分）都会写进数据库的 `jobs` 表，
按文件粒度记录完成情况（每个文件的标签是**逐个提交**的，所以断电最多丢当前这一张）。

下次启动时如果发现没跑完的任务，会弹窗告诉你「共 N 项，已完成 M，剩余 K」，选「是」就从中断处继续；
选「否」就标记放弃（原来的标签保留，随时可以重新跑）。

续跑时会自动跳过已经完成的文件（例如 WD14 已完成、只差 CLIP 的图只跑 CLIP）。

## 4.7 专用图库（Steam 式多库）：收录后源文件消失

**平时就点工具栏「导入图片…」走这条路**（类似 Lightroom）：选源文件夹 → 弹出缩略图网格让你勾选
（疑似重复的会自动标黄并默认不勾）→ 右侧设「移动/复制、导入时标签、导入后自动打标、写文件名」→ 开始导入。
导入完成后可自动接着跑自动打标，结果照常进待审核。

思路跟 Steam 的库文件夹一样：**每个盘一个专用图库目录**，审核通过的图片被「收录」进去，
之后就只在这些图库目录里检索，扫描来源清空后也不会重复扫描。

| 概念 | 说明 |
| --- | --- |
| 图库目录 | 默认 `<盘符>:\ImageTags`（可改），左树里标成绿色 `【图库】` |
| 扫描来源 | 你添加的原始目录，标成 `【来源】`，只用来导入 |
| 收录到图库 | 把选中图片**移动**到同盘图库目录；同盘移动是毫秒级 rename，源文件随之消失 |
| 检索范围 | 左侧「只检索图库」默认开启；图库存在时不会再去查来源目录 |
| 隔离区 | 图库目录下的 `.removed/`，删重/撤销都往这里放，随时能手动拿回来 |

用法：打标 → 审核 → 工具栏 **收录到图库**。也可以打开设置里的「审核完成后自动收录」，审核完就自动入库。
收录时会顺手把已确认的标签写进文件名（可关），并保留原有的子目录结构（系列仍然进系列文件夹）。

**图库目录会自动创建**：从任何盘（哪怕这个盘以前没有图库目录）导入时，程序会在该盘根目录按
「图库目录名」（默认 `ImageTags`）自动建好目录再放文件；导入对话框里每个盘的目标路径会实时显示状态，
也可以点「检查/创建图库目录」先建好并试写一次。

不可写的盘（只读盘、光盘/ISO、被锁的 BitLocker、无权限的系统目录、盘符未挂载）会**跳过并给出明确提示**，
不会中断整批导入、也不会动你的源文件；遇到这种情况可以取消勾选那些图，或在设置里把「图库目录名」
改成该盘下有权限的路径。

## 4.8 查重 / 相似图处理

工具栏 **查重 / 保留选择**：

- 检测：感知哈希（dHash/aHash，缩放、压缩、轻微改动都能抓到）+ CLIP 特征兜底（抓轻微裁剪/改色）；
- 按组展示，默认自动选**分辨率最高、体积最大**的那张作为保留建议，你可以自己改选；
- 两个动作：**移入隔离区**（`.removed/`，可恢复）或**永久删除**（二次确认）；
- 第三个动作：**判定为系列**——如果这几张其实是同一系列的不同页（比如漫画第 1、2 页翻拍），
  它们不是重复，用这个按钮按顺序并进同一个系列文件夹（不删文件）；
- **同一系列内部的相似不会被报警**（漫画页本来就长得像），只有「一方是系列页、另一方是单图」这种
  不对称相似才会提示你，并在组信息里标出「含系列页」；
- 勾选「合并被删图片的标签」后，被删那张的标签和框选区域会并入保留的那张，不会丢信息；
- **误报反馈**：点「不是重复」后，这一组以及其中每一对以后都不会再被提示。

## 4.9 分级识别（对齐 pixiv：全年齢 / R-15 / R-18 / R-18G）

工具栏 **分级识别**（默认会跟着「自动打标」一起跑）：

- 动漫图用 **WD14 自带的 4 类分级概率**（general / sensitive / questionable / explicit），这块很准；
- 真人照片用 **CLIP 零样本**的成人内容 / 猎奇提示词兜底，两边按 0.65:0.35 融合；
- 输出四级：**全年龄 / R15（轻度暗示）/ R18（成人向）/ R18G（猎奇）**，
  并自动打上对应标签（分类是「分级」），可以直接当筛选墙用；
- 左侧有**分级下拉筛选**，缩略图右下角显示彩色等级角标；
- 设置 → 分级里可以：
  - 把 WD14 的 `questionable`（半露/性暗示）算成 R18 还是 R15（默认 R15；想更严格就打开）；
  - 开启「浏览时对 R18/R18G 缩略图打码」，在公开场合翻库也不尴尬；
  - 决定分级标签是否直接生效（默认直接生效，不进审核队列）。

## 5. 标签体系（图谱）

工具栏 **标签体系（图谱）** 打开：左边是结构化树，中间是关系图。

- 一个标签可以**同时属于多个分类**，所以是图不是树；分类还能挂到更大的分类下；
- **手动连线**：点“连线模式”，先点父节点再点子节点；
- 节点可拖动、可随时增删，**自动排列**按层级排版，位置会记住；
- 这一层**完全独立于图片**：图片里只存 tag，改层级/分类/连线都不会影响图片；
- 在这里把标签改名（如「初音未来」→「hatsune miku」）会连带改名所有图片的标签，
  并可选**同步改写图片文件名**（复选框控制）。
- 右侧属性栏的**「中文名 / 备注」**就是标签的中文名（两者已合并成一个字段）：手填的优先，
  会用在界面显示和写进文件名；留空就用内置词典的翻译。旧数据里的「备注」会在启动时自动并进来。
- 搜索框输入中文或英文回车 → **会把视口用缓动动画滑到该标签**（起步即最高速、接近目标时减速），
  并自动展开它所在的分类；即使标签超出图谱的可见上限、被折叠在深层分类里也能定位。

## 6. 标签在磁盘上的样子（手机也能直接用）

约定：标签放在**末尾方括号**里（TagSpaces 风格，跨平台、任何文件管理器按名字都能搜到）。

```
单图：  [全年龄 白裙子 泳装].jpg               ← 默认只用标签命名；设置里可改回保留原文件名
系列：  <系列名> [全年龄 白裙子]/001.jpg      ← 文件夹名带标签，内部文件是页码
```

- **用中文名写盘**：写进文件名/文件夹名的是标签的中文名（在「标签管理」的「中文名（备注）」列里改，
  改完再点一次「写回文件名」就会用新名字；留空则用内置词典的翻译）。
- **首位是分级**：第一个标签固定是 `全年龄 / R15 / R18 / R18G`，方便在文件管理器里一眼筛出来。
- **父子只写最具体的**：同时有「裙子」和「白裙子」时只写「白裙子」；库里标签一个不少，
  检索写「裙子」照样能带出「白裙子」的图，模型学习也不受影响。
- 其余按**手动标签 / 系列 / 人脸 / 区域精修 / CLIP / WD14** 的优先级排，自动过滤
  `general` 这类噪声标签，最多 12 个、总长 ≤150 字符（防止 Windows 路径超限）；
- 标签总数、噪声阈值都能在设置里调；不想动磁盘就选「仅数据库」。数据库才是全集，
  文件名是给手机/其它软件看的一个子集。
- 重新扫描（换机器重建索引）时，文件名里的中文名会按「中文名 → 规范标签」还原回标签，
  并按从属关系把父标签一起补回库里。

## 7. 系列（漫画多页 / 连载）

选中 ≥2 张图 → **合并为系列**：

- 弹窗里可拖动排序、双击任意一页**手动改页码文件名**，可设起始页码与位数；
- 复制（默认保留原图）或移动；生成 `<系列名> [标签]/001.jpg`；
- 系列标签 = 成员标签并集，合并写入**文件夹名**；
- 网格里系列显示为**一份**（封面取第一页），带 `N页` 角标，双击进入看每一页。

### 系列内拖动改顺序（自动重命名）

双击进入某个系列后，网格会**按页码顺序**列出每一页（缩略图左下角有 `P001` 这样的页码角标）。
直接**拖动缩略图到目标位置**即可调整顺序：松手后自动重排页码，
并把文件重命名成 `001 / 002 / 003 …`（位数按设置里的「页码位数」，默认 3 位）。

- 可以一次选中多张一起拖（它们会保持相对顺序插到目标位置）；
- 两阶段改名（先临时名再定名），所以 `001 ↔ 002` 这种互换不会互相覆盖；
- 扩展名保持原样（`004.jpg` 挪到第一位就变成 `001.jpg`）；
- 只在系列视图里可拖动；普通列表按住拖动不会改变顺序（那里是按筛选条件排序的）。

## 9. 实测性能（本机 i9-14900HX / RTX 4070 Laptop）

| 环节 | 速度 |
| --- | --- |
| WD14 打标 | 4 张 3.6 秒（含模型加载），GPU |
| CLIP 特征 + 零样本打标 | 4 张 3.5 秒（特征只算一次，之后改标签秒级重打分） |
| 人脸检测 + 特征 | 4 张 2.8 秒 |
| 区域精修 | 每张图约 10 个候选窗口，毫秒~几十毫秒级 |

首次跑某个引擎会有几秒模型加载时间；CLIP 特征与标签打分是分开的，**改标签几乎瞬时生效**。

### 性能挡位（工具栏右侧「性能」，或 设置 → 性能）

| 挡位 | 做法 | 60 张实测（WD14 / CLIP） |
| --- | --- | --- |
| **榨干硬件** | 线程用满、进程高优先级、cudnn 穷举调优、缩略图 6 线程 | WD14 16.4 张/秒 ｜ CLIP 145 张/秒 |
| **均衡（默认）** | 线程按物理核、正常优先级、缩略图 4 线程 | WD14 16.0 张/秒 ｜ CLIP 227 张/秒 |
| **节能** | 小批次(4/8)、线程 1/3、进程降优先级、批间停顿 50ms | WD14 17.0 张/秒 ｜ CLIP 82 张/秒 |
| **只用 CPU（不占显卡）** | 强制 CPU，显存零占用 | WD14 2.9 张/秒 ｜ CLIP 50 张/秒 |

换算成整库（1000 张，WD14+CLIP 一起跑）：**均衡约 70 秒、节能约 70 秒（但系统占用低很多）、
只用 CPU 约 6 分钟**。

几个实测结论（都不靠猜）：

- **WD14 是瓶颈**（约 16 张/秒），CLIP 很快（100~200 张/秒）且图片特征只算一次；
- **批大小不是越大越好**：这台机器批 8 就已经把 GPU 跑满，堆到 16/32 反而更慢（显存来回搬），
  所以「榨干硬件」靠的是优先级 + 线程 + cudnn 调优 + 缩略图线程，而不是堆批次；
- 三个 GPU 挡位的**吞吐差别很小**，真正的区别是「对系统的打扰程度」：节能挡 CPU/GPU 占用明显更低，
  笔记本更省电更凉；只有「只用 CPU」是实打实的慢 5~6 倍；
- 改挡位立即生效（会重载模型），设置会被记住。

## 9.1 大批量导入不卡死（已修）

一次性导入几千张以前会卡住界面，原因是三处在**界面线程**上做了重活，现在都改掉了：

1. 导入列表给每张图**同步解码生成缩略图** → 改为后台线程池按需生成（只做可见区域）；
   实测单张冷缩略图约 20ms，3000 张同步生成会阻塞约 60 秒，这就是卡死主因；
2. 「全选 / 反选 / 取消勾选重复」逐个触发统计（O(n²)）→ 改为屏蔽信号后一次性统计；
3. 主界面刷新对每张图单独查一次标签 → 改为批量查询。

现在 3000 张的实测：列表填充 0.08s、全选 0.05s、主网格刷新 0.03s（都在界面线程上瞬间完成），
缩略图在后台慢慢补齐，可以随时继续操作或开始导入。

顺带修了一个 Windows 特有的坑：缩略图线程正在读文件时点「开始导入」，移动会报
`WinError 32（文件被占用）`。现在导入前会先停掉缩略图读取并释放文件句柄（PIL 改成读进内存后立即关闭），
移动失败还会自动重试。

## 9.2 AI 生图（可选扩展包）+ 手机/平板遥控（1.5）

### 扩展包（DLC）：AI 生图助手

主程序不带生图，装的时候（或之后在「更多 ▾ → 扩展包（DLC）…」）可以**可选安装**一个
「AI 生图助手」扩展包：把本机 ComfyUI 变成"选模型 → 写中文提示词 → 出图 → 自动入库"的一条龙。
**默认不启用**，要用自己在 DLC 管理窗口里打开。生图结果可以一键进图库，进了库就跟普通图片一样
能搜索、能审核、能看图。

它复用主程序的**同一份词库**（中文↔danbooru 标签、分类、从属关系），只额外保留"这个 tag 在目标
模型里认不认"的模型词表；模型本体不进包，按需下载（断点续传）。

### 手机/平板遥控（局域网，算力在 PC）

PC 端会开一个局域网服务（默认端口 47824，UDP 发现 47823），同网段的安卓设备连上后可以：

- **看图库**：和 PC 图库界面一样的条目（系列算一条、点开看内页），支持缩略图打包拉取、原图 Range 流式；
- **审核**：拉待审队列、提交/撤销（带乐观并发校验）、SSE 实时事件；
- **打标/写回/查重/导入/移动**：和 PC 侧同一套规则（移动端不能绕过 PC 去改文件名）；
- **遥控生图**：出图 / 局部重绘（涂哪改哪，换装）/ 图生图与图融合 / 参考图（IP-Adapter）/
  姿势线稿（ControlNet）/ 放大 —— 全在 PC 的显卡上跑，移动端只当遥控器；
- **只连 PC 与安卓之间**，两端都要点确认（对码 + PC 弹框），授权后除"离开局域网/关机"外不会掉线。

安全默认：配对码 + 设备号双重校验，未授权一律 401；删除/清理这类破坏性接口都要显式 `confirm`。

## 11. 已知限制 / 后续可做

- CLIP 零样本对**小众具体物体**（如某种特定玩具）不可靠，这类标签要靠框选 + 以图找图 + 样本积累；
- 区域精修目前用固定候选窗口 + 位置先验，不是真正的目标检测器。
  你框选的数据可以 **导出框选标注** 成 YOLO 数据集（`images.txt` / `labels/` / `classes.txt`），
  将来用它们训练一个小检测器再挂进来会更准；
- 人脸聚类是离线批量聚类，人员非常多时建议分库；
- 标签体系图谱在标签量特别大（上万）时建议先只挂常用的那部分（默认就只显示已归类的）。

## 12. 数据安全

- 全程离线：模型本地、推理本地、缩略图本地；
- 图片不会被上传；没有云端账号；
- 唯一联网的动作是「模型管理」里下载模型（走 hf-mirror），下载完可以彻底断网使用。
